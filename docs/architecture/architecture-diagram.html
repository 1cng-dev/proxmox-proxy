No fixed node list, anywhere
GET /api/nodes and the cluster-wide VM list call Proxmox live, every request — adding/removing a node needs no code change or restart.
Ownership ≠ node
vm_ownership ties a customer to a vmid. A VM migrating node1→node2→node5 never touches the ownership relationship — only the cached routing column, which self-heals automatically.
Client never picks the node
Node resolution is entirely server-side. A client-supplied :node URL segment is routing-only and gets overwritten before any Proxmox call.
Verified so far
